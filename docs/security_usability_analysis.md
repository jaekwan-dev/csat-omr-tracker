# 🔍 시스템 보안 및 사용성 문제점 분석 리포트

현재까지 개발된 기능들을 바탕으로 구조적인 문제점과 사용성 개선이 필요한 부분들을 정리했습니다. 상용 수준의 서비스로 발전시키기 위해 다음 항목들의 개선을 권장합니다.

## 🚨 보안상의 문제점 (Critical Security Issues)

### 1. 쿠키 기반 인증의 위조 취약점 (평문 저장)
- **현황**: 
  - 학생 로그인 시 세션 쿠키(`session`)에 학생 정보가 암호화 없이 **평문(Plaintext JSON)**으로 저장됩니다.
  - 교사 로그인 시 `teacher_session` 쿠키 값이 단순히 `"authenticated"` 문자열로 저장됩니다.
- **위험성**: 누구나 브라우저 개발자 도구(F12)를 열어 쿠키 값을 조작하면, **원하는 학생으로 위장(Impersonation)**하거나 비밀번호 없이 **교사(관리자) 권한을 획득**할 수 있습니다.
- **해결책**: JWT(JSON Web Token)를 도입하거나 `iron-session`과 같은 라이브러리를 사용하여 쿠키 데이터를 서버의 비밀키(Secret Key)로 암호화/서명해야 합니다.

### 2. 하드코딩된 교사 비밀번호
- **현황**: 교사 로그인 비밀번호가 코드 내부에 `"0000"`으로 고정되어 있습니다.
- **위험성**: 소스코드가 유출되거나 추측하기 쉬운 비밀번호로 인해 관리자 페이지가 쉽게 공격받을 수 있습니다.
- **해결책**: 환경 변수(`.env`)로 분리하거나, 교사 계정 테이블을 만들어 해시화(Bcrypt 등)된 비밀번호를 관리하도록 개선해야 합니다.

## 🛠️ 사용상의 문제점 (Usability Issues)

### 1. 학생 대량 등록(Bulk Upload) 기능 부재
- **현황**: 교사가 `[학생 관리]` 페이지에서 한 명씩 수기로 학생을 추가해야 합니다.
- **문제점**: 수십~수백 명의 학생이 있는 학교/학원 환경에서는 한 명씩 입력하는 것이 매우 비효율적입니다.
- **개선안**: 엑셀(CSV) 파일을 업로드하여 수백 명의 학생 데이터를 한 번에 등록하는 기능을 추가해야 합니다.

### 2. 학생 OMR 답안 임시저장 기능 부재
- **현황**: 학생이 OMR 마킹 중 브라우저를 실수로 새로고침하거나 뒤로가기를 누르면 모든 마킹 데이터가 초기화됩니다.
- **문제점**: 45문항을 마킹하다가 실수로 데이터가 날아가면 사용자 경험(UX)에 큰 악영향을 미칩니다.
- **개선안**: `localStorage`를 활용하여 마킹 시점마다 브라우저에 임시 저장하고, 재접속 시 이어서 마킹할 수 있도록 복구 기능을 제공해야 합니다.

### 3. 시험(정답/배점) 일괄 입력의 불편함
- **현황**: 교사가 새 시험을 등록할 때, 30~45개에 달하는 문항의 정답과 배점을 일일이 클릭하여 입력해야 합니다.
- **문제점**: 수능 시험지 등록 작업이 매우 번거롭고 시간이 오래 걸립니다.
- **개선안**: 
  - 배점 일괄 적용 버튼 (예: "전 문항 2점 부여 후 특정 문항만 수정")
  - 문자열 한 줄 입력 기능 (예: `13425...` 처럼 텍스트로 치면 자동으로 각 문항 정답으로 분배되는 기능)

### 4. 제출 이력(History)의 빈약한 분석 피드백
- **현황**: 제출 이력 페이지에서 점수와 맞은 개수만 제공됩니다.
- **개선안**: 학생이 취약한 유형을 분석해주거나, 학급 평균 대비 본인의 위치를 차트로 보여주어 학습 방향을 잡아주는 디테일이 추가되면 훨씬 유용할 것입니다.
