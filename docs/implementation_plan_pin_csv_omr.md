# 🚀 시스템 고도화 및 보안 강화 계획서

말씀하신 대로 현재의 `학번 + 이름` 로그인 방식은 같은 반 친구들끼리 너무 쉽게 알 수 있는 정보이기 때문에 **대리 시험**이나 **성적 무단 열람**의 위험이 큽니다. 이를 방지하기 위한 보안 대책과 함께 요청하신 두 가지 기능의 구현 계획을 정리했습니다.

---

## 🛡️ 1. 학생 대리 로그인 방지책 (보안 대책)

이 문제를 해결하기 위해 가장 추천하는 방식은 **학생별 고유 PIN 번호(4자리 비밀번호)** 제도를 도입하는 것입니다.

**[PIN 번호 도입 시나리오]**
1. **DB 스키마 추가**: 학생(`Student`) 모델에 `pinCode` 필드를 추가합니다.
2. **자동 발급**: 선생님이 학생을 등록할 때 무작위 4자리 숫자(예: `4912`)가 자동으로 발급됩니다. (물론 선생님이 엑셀로 일괄 지정하거나 수동으로 변경할 수도 있습니다.)
3. **배포**: 선생님은 학생 관리 페이지에서 학생 명단과 PIN 번호를 엑셀로 다운로드하여 학생들에게 나누어 줍니다.
4. **로그인 변경**: 학생은 로그인 시 `학번`, `이름` 외에 **`PIN 번호 4자리`**를 추가로 입력해야만 접속할 수 있습니다.

> [!IMPORTANT] 
> **User Review Required**
> 위 PIN 번호 방식이 학교/학원 현장에서 사용하시기에 적합한가요? 만약 학생들의 생년월일이나 전화번호 뒷자리 등을 비밀번호로 쓰는 방식을 선호하신다면 알려주세요. (보안상 랜덤 PIN 발급 후 선생님이 배부하는 방식을 가장 추천합니다.)

## 👥 2. 엑셀(CSV)을 이용한 학생 대량 등록 기능

수십~수백 명의 학생을 한 번에 등록할 수 있는 기능을 추가합니다.

### Proposed Changes
- **API 개발 (`POST /api/teacher/students/bulk`)**
  - 업로드된 CSV 파일 텍스트를 파싱하여 학번 중복을 검사하고, 여러 학생을 한 번의 트랜잭션으로 DB에 일괄 저장합니다.
- **UI 변경 (`/teacher/students/page.tsx`)**
  - [학생 추가] 버튼 옆에 **[CSV 대량 등록]** 버튼을 추가합니다.
  - 양식에 맞는 CSV 파일(학번, 이름, 학년, 반)을 첨부하면 화면에서 미리보기(Preview)를 제공하고 최종 등록을 누를 수 있게 구현합니다.

## 💾 3. OMR 마킹 중 실수 방지를 위한 임시저장 기능

학생이 스마트폰이나 PC로 45문항을 마킹하다가 실수로 뒤로가기를 누르거나 창이 닫혔을 때, 마킹 내역이 날아가지 않도록 보호합니다.

### Proposed Changes
- **브라우저 임시 저장소(`localStorage`) 활용**
  - `OmrSheet.tsx` 컴포넌트에서 학생이 번호를 클릭할 때마다 실시간으로 브라우저의 `localStorage`에 데이터(`omr_answers_시험번호_학번`)를 저장합니다.
- **복구 로직**
  - OMR 페이지에 처음 진입 시, `localStorage`에 임시 저장된 마킹 내역이 있다면 자동으로 불러와 마킹 화면을 복구합니다.
- **초기화 로직**
  - [최종 제출] 버튼을 눌러 채점이 완벽하게 끝난 경우에만 `localStorage`의 데이터를 안전하게 비워줍니다.

## 🛠️ 진행 순서 제안
세 가지 모두 중요한 기능입니다. 승인해 주시면 다음과 같은 순서로 한 번에 개발을 진행하겠습니다.
1. **DB 스키마 변경** (`pinCode` 추가) 및 **로그인 인증 로직 수정**
2. **학생 대량 등록(CSV)** 기능 완성 (PIN 번호 포함 처리)
3. **OMR 임시저장** 로직 개발

계획에 동의하시거나, PIN 번호 시스템에 대해 다른 의견(예: 전화번호 뒷자리를 초기 비번으로 쓴다 등)이 있으시면 편하게 말씀해 주세요!
